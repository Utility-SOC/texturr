# Agentic analysis with n8n

> **Untested with a real language model.** The wiring is verified with real n8n, real MCP nodes and the real
> texturr service, but every agent run so far used a scripted stand-in that follows a fixed plan. How a
> real model decides what to merge, split and label has not been measured. Check its output on your own
> data before relying on it. Details in [What has and has not been tested](#what-has-and-has-not-been-tested).

An AI agent reviews texturr's automatic grouping, fixes it, names every group, and hands back your
spreadsheet with the groups written beside each answer. Built in [n8n](https://n8n.io) so it can be
inspected, edited and scheduled without writing code, and runs entirely on your own machine.

```
 upload .xlsx/.csv ──► texturr: parse, embed, group (auto k)  ──►  AI Agent (your chat model)
                                                                     │  MCP tools:
                                                                     │  get_overview, get_cluster_examples,
                                                                     │  merge_clusters, split_cluster,
                                                                     │  move_responses, set_cluster_label,
                                                                     ▼  finish_analysis
 grouped spreadsheet  ◄──  texturr: write Cluster + Theme beside each answer  ◄──  finished grouping
```

## Why an agent

Statistics can pick a sensible number of groups, but they cannot tell that two groups mean the same
thing. On the bundled 24-comment example (four real themes) texturr's automatic count gives seven
groups, and the two "price" groups have a centroid similarity of only 0.43, nowhere near enough for
any threshold to merge them without also merging unrelated groups. I tested threshold-based merging
and other selection rules against Banking77 (see the main README): none beat plain silhouette. What
fixes it is reading the responses, which is what the agent does: it merges groups that express one
theme, splits mixed ones, moves single answers that landed in the wrong group, and then writes labels
based on what it actually read. Every change is recorded in the session history.

## Quick start

```bash
cp .env.example .env                      # then put a token in it (command inside the file)
docker compose up -d --build              # texturr service (private) + n8n (localhost:5678)
./n8n/bootstrap.sh                        # imports both workflows, creates the credentials
docker compose --profile ollama up -d     # optional: a local model server
docker compose exec ollama ollama pull llama3.1
```

Open <http://localhost:5678>, create the owner account, and open a workflow:

- **texturr agentic analysis (upload form)** shows a page where you upload a spreadsheet and name the
  column (a header such as `Comments`, or a letter). Activate the workflow and share its form URL, or
  use "Execute workflow" to test. You download the grouped spreadsheet when it finishes.
- **texturr agentic analysis (files)** is the batch version: drop a file in `n8n/data/in/`, set
  `file_name` and `column` in the Settings node, run it, and `n8n/data/out/` receives the annotated
  spreadsheet and an HTML report.

## Choosing the chat model

The agent needs a model that supports **tool calling**. Select it in the "Chat model" node, or
regenerate the workflows for a different default:

| Model | How | Data leaves this machine? |
| --- | --- | --- |
| Ollama (default) | `--chat-model ollama`; credential "Ollama (local)" is created by the bootstrap script | No |
| llama.cpp, LM Studio, vLLM or any OpenAI-compatible server | `--chat-model openai`, then set the credential's base URL to your server | No, if the server is local |
| OpenAI, Anthropic, others | add your own API key credential in the n8n UI | **Yes** |

```bash
python3 n8n/build_workflows.py --chat-model openai --model-name granite-4.2-8b    # writes n8n/workflows/
```

**What a hosted model would see:** the overview (3 example responses per group) and whatever
examples the agent asks for (up to 25 per call). That is verbatim survey text. For sensitive data use
a local model. The vetted-model shortlist in the main README (`texturr.py models`) lists
permissively licensed, first-party models that fit.

## How the pieces fit

- `server.py` (`texturr.py serve`) is the texturr service: a REST API for the pipeline steps and an
  MCP endpoint (`/mcp`, Streamable HTTP) for the agent's tools. It keeps sessions **in memory only**,
  requires a bearer token, binds loopback by default, and never logs request bodies or response text.
- `session.py` holds the editable state. The agent's tool arguments are validated, text is
  sanitized, labels are length-limited, and a finished session is locked.
- The two workflows are generated by `build_workflows.py`, so they stay in sync with the server's
  tool list (a test enforces it). Credentials are referenced by name, never embedded.

## Security notes for sensitive data

- The texturr container publishes no ports; only n8n can reach it. The n8n editor is bound to
  `127.0.0.1`. If you expose either, put authentication and TLS in front.
- The compose file tells n8n **not to keep execution data** (it contains the survey text) and to keep
  uploaded files in memory. If you change this, the text will be written to the n8n volume.
- Results are written to `n8n/data/out/` (annotated copy and HTML report). Handle them at the same
  classification as the input. The upload form returns the annotated copy through the browser instead.
- n8n's form pages load a web font and favicon from the internet in the user's browser. No survey
  data is sent, but an air-gapped browser will show the page with default fonts.
- The token in `.env` guards the texturr API. `bootstrap.sh` writes it to a file only for the
  duration of the import, then deletes it, but n8n then stores it (encrypted) as a credential.

## What has and has not been tested

Verified with real components: n8n 2.41.6 executing both workflows (the file workflow headlessly, the
upload form through a real multipart upload and the completion page), the real n8n AI Agent node,
the real MCP Client Tool node discovering and calling texturr's tools over Streamable HTTP,
including parallel tool calls and tool errors, and the real texturr service with real embeddings.

Also verified: the Docker image builds and runs offline as a non-root user on a read-only
filesystem, the texturr port is unreachable from the host and reachable from n8n, unauthenticated
requests get 401, `bootstrap.sh` imports the workflows and credentials and deletes its temporary token
file, and the whole agent workflow runs inside the compose network. For data retention I searched the
entire n8n volume (including the SQLite database) for phrases from the uploaded spreadsheet after a
run: with this compose file there were none, whereas n8n's default settings left the text in four
files. An execution record (without content) is still created.

**Not verified:** how a real LLM behaves. The language model in those runs was a scripted stand-in
(`n8n/testing/fake_llm.py`) that follows a fixed plan, so the tests show the wiring is correct, not
that a model makes good merge decisions. Small local models vary a lot at tool calling; try yours on
a sample first and read the agent's summary. The decision quality is the thing to evaluate next
(see `eval/label_eval.py`).

## Testing it yourself without a model

```bash
python3 n8n/testing/fake_llm.py --port 11500        # scripted OpenAI-compatible stand-in
python3 n8n/build_workflows.py --texturr-url http://127.0.0.1:8765 --chat-model openai \
        --model-name fake-agent --out /tmp/wf
```

Create an OpenAI-compatible credential pointing at `http://127.0.0.1:11500/v1`, import the
workflow, and run it. The fake merges the two most similar groups, labels everything and finishes.
